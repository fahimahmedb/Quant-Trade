## Reproduced failures and localized roots

1. Save blindly replaced the file. A stale heartbeat could restore IDLE over an
   acknowledged PAUSED/STOPPED state. Stale saves could erase completed-cycle
   consumption and processed fingerprints. Two processes could both acknowledge
   conflicting saves from one prior state. Root: no observed-snapshot comparison
   spanning publication and no cooperative file lock.
2. Failed publication left mutated RAM alive; losing an ACK after a successful
   write left the instance's assumed state unqualified. Shared heartbeats/saves
   could enter during publication/recovery and have their update overwritten by
   rollback. Root: mutation, persistence and recovery lacked one instance lock
   and reconciliation to the actual durable body.
3. Loading accepted duplicate JSON keys and nonfinite/overflowed numeric values
   the writer itself refuses. Conflicting statuses/counters could be silently
   collapsed, and load versus save could disagree about admissible bytes.
   Root: default JSON parsing plus no finite-wire admission on read.

These are three grouped repair items, not 32 independent defects.

## Narrow repair and compatibility

Track observed documents per target path in runtime-only instance metadata.
Within the instance RLock and a file flock, compare canonical serialized bodies
before publication; refuse a conflicting stale writer with CampaignStateConflict.
An exact durable retry does not rewrite the file. On failure, adopt a valid actual
durable snapshot, or retain the last observed in-memory snapshot if the file is
unreadable; rethrow the error and do not manufacture a successful ACK. The invalid
file remains untouched. Heartbeat holds the same lock through its field update,
save and recovery. A concurrent creator loads the winner rather than replacing it.

Read rejects duplicate keys at any nesting and JSON numeric nonfinites, including
1e309 overflow. Existing dataclass fields/defaults and JSON schema stay intact;
private locks/snapshot metadata are not dataclass fields. A new snapshot path can
still be written. Existing load_or_create behavior for a different requested ID
on an existing file is preserved, not silently redefined as an identity migration.
No new queue, scheduler, distributed transaction or authority service is built.
