# `QUANT_FASTLANE_HPIT_V1`: protocol clarifications, filed before any outcome access

Sealed protocol `sha256:78b3a501e609e135def64783f53f0f02ecbc8df2ea3d86e99c4d00fa206a6999`, seal commit `9c8350d`. This file changes nothing in the seal. It records the places where the sealed text does not fix one reading, the options, and the choice the evaluation engine (`src/quant/fastlane/{evaluation,inference,screen,verdict}.py`) implements. Where one option was more conservative, the engine takes it.

When this was written, no price vendor was licensed. No price, return, market cap or delisting status had been read in any split. The holdout request pins the code fingerprint, so these choices are frozen before the look. Any change must be made, committed and pushed before `HOLDOUT_REQUEST.json` exists.

| # | Point the sealed text leaves open | Options | Implemented (and why) |
|---|---|---|---|
| C1 | `FROZEN_FV_10S`: which vendor session an EDGAR date with no session belongs to, for the 10-session formation window (the D07-O1 point) | `PREVIOUS_REGULAR_SESSION`, `NEXT_REGULAR_SESSION` (the only two D07 allows) | **NEXT**: the same rule as the census weekday proxy that chose the grid, and it never attaches a filing to a session that closed before the filing was public. Crossing state is computed from events inside the split's price window only. It converges after 10 sessions, and each window starts at least 60 sessions before its split. |
| C2 | Benchmark on the entry session. The position earns open to close, while `r_SPY,t` is close to close. Same issue for a next-open exit. | (a) the sealed formula as written, with the same `r_SPY,t` for every position; (b) a matched SPY open-to-close or close-to-open return | **(a), as written.** In expectation it subtracts the SPY overnight return that the position did not earn on its entry day, so it biases alpha down: about 252 × (SPY overnight drift)/h, i.e. about 0.3 %/yr at H20 and 1.3 %/yr at H5 if the overnight drift is about 6 %/yr. |
| C3 | The "one-sided 95 % upper bound" behind INCONCLUSIVE, and how finalists combine | bootstrap percentile-t, fixed-b HAC, or both; per finalist or multiplicity-adjusted | **max(bootstrap percentile-t UB, fixed-b HAC UB)** per finalist, unadjusted. NO_GO then needs both methods to exclude 3 %/yr. Overall verdict: GO if any finalist passes every leg (Holm controls FWER); else INCONCLUSIVE if any finalist's UB ≥ 3 %/yr; else NO_GO. |
| C4 | "net result positive at 1x C0 after frictions" | net alpha > 0; net USD P&L > 0; both | **Both**: net annualized alpha > 0 and net paper P&L in USD > 0 (a stricter GO). |
| C5 | Friction inputs for the exit leg | reuse entry ADV20, σ and spread; or recompute over "the sessions before the leg" | **Before each leg**, for both legs, as the text says for σ and the spread: ADV20 over present bars among the 20 prior sessions (entry ADV20 if none); σ = sample stdev of log total returns between adjacent sessions among the 20 prior (entry σ if fewer than 2); Abdi–Ranaldo over adjacent pairs in the 21 prior sessions, adjusted for splits and dividends, with the floor alone if fewer than 15 pairs. The untradeable threshold gates entries only: a held position is always closed and pays its exit costs. |
| C6 | When and how the delisting treatment is booked | at the scheduled exit, after the 20-session look, or after the last trade; with or without an exit cost | Booked **on the session after the last traded bar**, as last close × (1 + class return). The position then leaves invested capital, so cash is never counted as alpha. Its slot stays held until the scheduled exit, with no recycling. No exit friction, since no trade happens. Class = the earliest vendor `DELISTING` action dated on or after the last trade, mapped through the committed `DELISTING_CLASS_MAP.json`. An unmapped code, or no action at all, gives UNKNOWN (−30 %, stress −100 %). |
| C7 | The 20-session look for a missing exit bar runs past the price-window end | extend the window, truncate, or drop the event | **Truncate at the window end, then apply the delisting treatment** (the count is logged). Discovery and walk-forward windows end at their split ends, so no holdout price becomes reachable. |
| C8 | Missing bars during the hold; ex-date conventions | carry the last price, or apply a rule | **Carry the last close (r = 0); the gap is booked at the next bar.** SPLIT (new shares per old) and CASH_DIVIDEND (cash per share held) apply on (previous bar, current bar]. Actions dated on the entry session are ignored because the buy happens at the ex-date open. Other action kinds are counted and never applied. |
| C9 | Share rounding | whole shares, or fractional | **Fractional**: `a_j` is the notional and the commission is on `a_j / open`. |
| C10 | "20 complete vendor bars before entry" | bars on each of the 20 vendor sessions just before entry, or the security's last 20 bars | **Each of the 20 vendor sessions immediately before the entry session.** ADV20 is the mean raw close × raw volume over them. The USD 1 floor applies to the raw close of session e−1. |
| C11 | Point-in-time mapping date and ambiguity | the filing date or the entry date; how to treat more than one security | Mapped **as of the entry session**. More than one distinct vendor security valid on that date counts as ambiguous, unresolved and counted. |
| C12 | Studentization and gaps in the bootstrap and HAC | several standard variants | The series runs over vendor sessions from the first to the last invested session. Sessions with no position are gaps, handled by linearizing the ratio mean (so the mean is the sealed alpha mean). Observed studentizer: Bartlett window of 80 (Götze–Künsch). Bootstrap studentizer: the variance of the k = ceil(n/80) resampled block means. t* is centred at the MBB expectation. p = (1 + #{t* ≥ t}) / (1 + B). The UB is percentile-t. HAC bandwidth M = 0.1 n over the same span. The RNG is SplitMix64, so results do not depend on the Python version. |
| C13 | Deflated Sharpe inputs | per-session or annualized SR; which trials enter V[SR]; N | Per-session SR of discovery net `r_ex` (sample sd), with biased skewness and kurtosis. V[SR] = sample variance across the discovery SRs of the evaluated (not dropped) variants. N = `n_trials_for_dsr` from the ledger, which counts discovery **and** walk-forward records (2 × M_declared for one screen). At the look, N = max(the request's N, the current ledger N). |
| C14 | "Eligible counts" in the post-eligibility adequacy recheck | before or after the purge; whether the entry-bar check counts | After the value floor and the purge; pre-entry checks only (mapping, 20 bars, ADV20 > 0, close ≥ USD 1, ADV20 ≥ USD 100k); not the entry-bar check; divided by `census.split_years`. |
| C15 | A vendor attestation that is not go_eligible | the verdict `NOT_GO_ELIGIBLE` (`prices.resolve_verdict`), or the GO leg simply fails | **Sealed outcomes only**: the GO leg fails and the verdict is INCONCLUSIVE or NO_GO, with the evidence label reported. `evaluate-holdout` also **refuses to open the holdout** on such a vendor, so the one look is never spent on evidence that can never be GO. |
| C16 | Kiefer–Vogelsang one-sided 5 % critical value (Bartlett, b = 0.1) | cite KV (2005), or simulate | The KV (2005) polynomial could not be verified here (no download). Recalled as 1.6449 + 2.1859b + 0.3142b² − 0.3427b³ = **1.8663**. **Simulated instead** (`inference.simulate_fixed_b_null`, i.i.d. N(0,1), T = 2000, M = 200, R = 200,000, seed 20260924): q(0.05) = **1.8373** (Monte Carlo s.e. about 0.006; T = 1000 gives 1.8370). p-values interpolate the stored table. **Lead decision (2026-09-25, before any outcome access)**: use the MORE conservative of the two at every level. `inference.conservative_scale()` = max(1, KV-polynomial / simulated quantile at 10 %, 5 %, 2.5 %) = 1.0158. Positive statistics are divided by it before the table lookup, and the critical value is multiplied by it, giving cv(0.05) = 1.8663. A mis-recalled coefficient can only tighten the co-check. Test: `test_fixed_b_co_check_is_never_looser_than_kiefer_vogelsang`. |
| C17 | Holdout exits past the vendor calendar | truncate, or refuse | **Refuse** (`CalendarIncomplete`) until the vendor calendar covers every scheduled exit (the window ends 2026-09-30). |
| C18 | Trial identity for the ledger | per variant and split, or tied to the configuration | `variant|split|screen-config digest` (code fingerprint, prereg, event-table digest, vendor identity and manifests). Every declared variant gets both a discovery and a walk-forward record, including dropped ones. A replay is idempotent. A changed configuration makes new trials, which raises N_trials. |
| C19 | Romano–Wolf and finalist ties | several variants | One-sided studentized step-down on discovery net `r_ex`, aligned to a common span with shared block draws (sealed block, B and seed). Hansen SPA is reported only. Equal DSRs are broken by variant id. |
| C20 | What the robustness seeds change | tie-break only, bootstrap only, or both | **Both**: slot tie-break and bootstrap draws. Reporting only. |
