# Oracle Research Lab V1 acceptance boundary

Owner decision, 2026-10-20 Europe/Paris: finish the existing Oracle H24 work as
V1, leave the qualified lab running, then scope V2 with a specification, test
strategy and deployment plan. This does not redefine the whole Quant System as
its worker/runtime subsystem and does not authorize any new outcome access.

## V1 includes

- The existing canonical Research OS, queue and lane contracts, not a replacement
  architecture or a second task authority.
- Oracle A1 CPU-only bounded systemd wakes, fresh GitHub state every wake,
  canonical claim/lease/CAS, one lineage per wake and durable per-stage records.
- A local GPT-OSS implementation behind ModelBackend, qualified on the actual
  2 OCPU / 12 GiB VM for structured output, scientific negative cases, latency
  and memory. An experimental model candidate is not a quality PASS.
- Real Legacy blob verification, the normalized current frozen corpus, ASML
  anti-redetection and blocking of unresolved structural overlap.
- Existing pre-outcome documentary stages and independent challenge/integration
  boundaries. Model commentary is unverified and cannot grant scientific PASS.
- CI, live inference, real GitHub writes and claim/recovery canaries, two
  automatic scheduled wakes, and final exact-release operational evidence.
- Restart recovery, logs, bounded resources, durable unattended GitHub identity,
  operational commands and truthful blockers. No credentials in Git.

V1 acceptance requires the actual service/timer enabled and active and evidence
of automatic execution. Code completion, CI or read-only wakes alone cannot
establish ORACLE_H24_RESEARCH_LAB=RUNNING.

All four authority flags remain false: economic experiment, prospective
observation, real capital and live trading. Allocation, sizing and orders remain
forbidden. Correlation remains UNAVAILABLE and marginal contribution
NOT_ESTIMATED absent admissible evidence. Idle/blocked with an explicit receipt
is valid runtime behavior, not evidence of research throughput or edge.

## Explicit V1 limitations / V2 candidates

The existing documentary adapters are not a complete autonomous collection and
research system. A fully qualified real-source Quant adapter, broader and fresher
Fundamental/Event/Flows discovery, stronger independent scientific evaluations,
complete Live Lab display integration, empirical Portfolio Map estimates, and
prospective/decay farming are not claimed complete by launching the timer.
Prospective capabilities additionally require a separate authority decision.

Before V2 implementation: define capability-by-capability inputs/provenance,
outputs/contracts, scientific acceptance criteria and measurable throughput;
then negative/regression, reproducibility, integration and live canary tests;
then resource budgets, migrations, gated rollout, rollback and observation.
Keep V1 running on its exact qualified release while developing V2 separately.
