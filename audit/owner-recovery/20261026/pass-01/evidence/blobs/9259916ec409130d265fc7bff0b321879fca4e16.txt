## WHAT_GAP_WAS_PROVEN

The canonical Trial Ledger schema and Experiment Registry already distinguish four explicit effective-trial states: `UNKNOWN`, `KNOWN`, `ESTIMATED`, and `PARTIALLY_BOUNDED`. The registry accepted all four with strict finite/non-negative semantics, but Validator v3 had a second local implementation that accepted only `UNKNOWN` and `KNOWN`. The same Trial Ledger record could therefore be admissible to the registry and rejected by the Validator solely because two copies of the scientific law had drifted.

## WHAT_CHANGED

- Promoted the registry's existing trial-accounting validation into public canonical `validate_trial_accounting()`.
- Registry creation now calls that canonical function directly; no behavior is weakened.
- Validator's duplicate `_trial_accounting_valid` implementation is reduced to a boolean adapter over the same canonical function and error type.
- The historical `quant.factory.experiments` compatibility surface re-exports the canonical function rather than introducing another implementation.
- Added adversarial tests covering all four admissible states and invalid UNKNOWN-with-estimate, bool, NaN, Infinity, negative/unsupported-state semantics.

Canonical semantics now are:
- `UNKNOWN` => estimate MUST be null;
- `KNOWN`, `ESTIMATED`, `PARTIALLY_BOUNDED` => estimate MUST be a real int/float, finite and >= 0;
- bool is never numeric evidence;
- observed attempt count MUST be a non-negative integer and never bool;
- optional hypothesis/generation identity checks remain available to registry binding.
