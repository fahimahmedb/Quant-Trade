# FINAL THREE CRITICAL PATHS

## SCIENTIFIC_CRITICAL_PATH

`EXACT_FROZEN_WITNESS_IDENTITY -> EXPLICIT_BOUNDED_RESEARCH_AUTHORITY -> VALID_PIT_SOURCE_CAPTURE -> DETERMINISTIC_ISOLATED_EXECUTION -> OUTCOME_ISOLATED_EVALUATION/ADJUDICATION -> DENOMINATOR_AND_MULTIPLICITY_APPEND -> IMMUTABLE_SCIENTIFIC_MEMORY`

FIRST_BLOCKING_POINT_SCIENTIFIC=`AUTHORIZED_VALID_PROSPECTIVE_BBO_CAPTURE`

The selected witness is already frozen. Its recovered attempt correctly parked because required BBO fields were invalid/missing. If existing authority does not explicitly cover the new bounded capture, authority is the first legal stop; once authority is explicit, valid quant capture is the first factual blocker. Full scheduler autonomy is not required for this path.

## AUTONOMY_CRITICAL_PATH

`EXACT_AUTHORITY_AND_RESEARCH_OBJECT -> TASK_MATERIALIZATION -> LEASE/RETRY/RECOVERY -> RUNNER/EXECUTOR -> EVALUATOR -> SCIENTIFIC_SINKS/MEMORY -> REPLAY/CONTINUATION`

FIRST_BLOCKING_POINT_AUTONOMY=`UNPROVEN_SINGLE_CANONICAL_IDENTITY_CONSERVING_TASK_TO_SINK_LINEAGE`

Individual components, leases, runners, evaluators and sinks exist with qualification evidence, but the inspected evidence does not establish one continuous canonical lineage across all of them with restart/replay semantics and no identity loss.

## PROMOTION_CRITICAL_PATH

`OWNER_SELECTED_CANDIDATE_SHA_AND_GATE_POLICY -> EXACT_LOCAL_QUALIFICATION -> EXACT_HOSTED_QUALIFICATION -> REMOTE_HEAD_EQUALITY -> FORMAL_OWNER_PROMOTION -> INSTALLED_RELEASE_RECEIPT -> DEPLOYED_RUNTIME_IDENTITY`

FIRST_BLOCKING_POINT_PROMOTION=`NO_FORMAL_OWNER_SELECTION/PROMOTION_OF_AN_EXACT_TECHNICAL_CANDIDATE`

The old one-shot remains non-qualified. A successor C0 membrane branch now has exact-hosted PASS on `13721384...`, but that scoped technical PASS is not a formal program promotion and does not establish installed runtime identity.

## COMMON_CRITICAL_PREFIX

`EXACT_IMMUTABLE_IDENTITY -> EXPLICIT_AUTHORITY/CONTRACT -> PROVENANCE_BINDING`

All three paths require an immutable object identity, a lawful authority/contract boundary and evidence linking later claims to the exact object actually used.

## DIVERGENT_REQUIREMENTS

- Science additionally requires prospective/PIT-valid observations, frozen analysis, outcome isolation, multiplicity/denominator accounting and durable scientific memory.
- Autonomy additionally requires task/lease/runner/evaluator/sink continuity, idempotency, crash/replay and unattended continuation.
- Promotion additionally requires exact-head local/hosted gate results, formal Owner decision, release/install identity and runtime observation.

## Non-implications

- A scientifically valid isolated result does not prove autonomy or promotion.
- A fully autonomous loop does not prove the hypothesis is scientifically valid.
- An exact-hosted engineering PASS does not prove Owner promotion, deployment or economics.
- A promoted/deployed SHA does not prove a strategy has edge.

## Post-disclosure change from prior roadmap

The prior sequences were directionally correct about identity, C0 integrity, continuation and eventual renewal, but too easy to read as one serial critical path. The final program separates the three paths and allows science to progress while autonomy and promotion evidence mature in parallel.
