# DO-NOT-BUILD CHALLENGE

Default law: absence of proof for a missing function means `DO_NOT_BUILD_YET`, not permission to create a subsystem.

| Proposed build | Decision | Exact missing function, if any | Authorized smallest response |
|---|---|---|---|
| New Discovery | DO_NOT_BUILD_YET | No missing discovery lifecycle proven; existing Discovery/RI/F/V3 surfaces exist | Reuse existing admission/discovery and run one real witness |
| New Research OS | DO_NOT_BUILD_YET | No evidence that lifecycle absence is the blocker | Reuse existing Research OS contracts and memory |
| New scheduler | DO_NOT_BUILD_YET | Mono-lineage join is unproven, but existing Control/Oracle/lease primitives exist | Evidence-first WP2; at most one narrow proven join repair |
| New Scientific Memory | DO_NOT_BUILD_YET | Historical denominator coverage is incomplete, not evidence of absent memory | Append/crosswalk existing memory/ledger; preserve UNKNOWN history |
| Large Advanced Research subsystem | DO_NOT_BUILD_YET | No demonstrated functional gap requiring a new owner/control plane | Compare/reuse existing capabilities; add only typed seam if proven |
| Generic data platform | DO_NOT_BUILD_YET | Selected witness needs exact BBO fields, not a platform | One bounded acquisition/parser repair if semantics remain frozen |
| Second Candidate system | DO_NOT_BUILD_YET | Candidate/admission identity fragmentation is the problem, not absence of candidate machinery | Pick one owner/crosswalk existing IDs |
| Second economic layer | DO_NOT_BUILD_YET | Economic transport/validation not yet demonstrated, but D0/Desk/Book/Learning/economic objects already exist | Later narrow expression/identity transport only for an eligible real result |
| New frontier-renewal control plane | DO_NOT_BUILD_YET | Renewal contract is partial/program-relevant but not first-science blocker | Reuse existing replenisher/planner and add a bounded successor receipt only when needed |
| New independent adjudicator subsystem | DO_NOT_BUILD_YET | C0 counting/membrane defects were narrow and have successor repairs | Reuse repaired adjudication; prove authentic independent review evidence when required |

## Functions that may justify narrow code later

1. Exact BBO acquisition/parsing boundary for `disc-crypto-book-pressure-prospective-l1-v0`, only if source semantics are unchanged.
2. One missing native identity/receipt adapter in the autonomy chain, only after WP2 proves the exact absent join.
3. One lossless research-to-economic expression/identity adapter, only after an actual scientifically eligible result requires economic transport.
4. One bounded renewal/successor receipt, only after a frontier actually requires continuation and existing replenishment cannot express the obligation.

None of these functions justifies a new architecture owner by itself.
