# THREE SEPARATE CRITICAL PATHS

## SCIENTIFIC_CRITICAL_PATH

1. Exact candidate/hypothesis identity and predeclared/frozen protocol.
2. Named source/data observations with PIT availability, immutable provenance and required universe/frequency.
3. Deterministic execution against the frozen protocol; isolated deterministic harness is sufficient if provenance is complete.
4. Explicit transaction/execution-cost assumptions appropriate to the experiment.
5. Evaluator and scientifically independent adjudication with outcome-leakage controls.
6. Denominator/multiplicity/exposure accounting and immutable result identity.
7. Durable Scientific Memory append/feedback preserving the lineage.
8. Economic Identity / Portfolio Readiness only when the claim is economic readiness rather than scientific validity alone.

No scientific property requires the canonical autonomous scheduler before this data/protocol can be evaluated.

## AUTONOMY_CRITICAL_PATH

1. Exact authority/current-head identity and frozen research contract.
2. Qualified source -> proposal admission / ledger.
3. Discovery -> Candidate -> factory/freezer.
4. Candidate/protocol -> task materialization with conserved lineage identity.
5. Control Plane routing/capability/authority validation.
6. Oracle selection -> claim/lease -> retry/recovery.
7. Runner/executor -> evaluator.
8. Independent adjudication -> scientific sink/Scientific Memory.
9. Replenishment/continuation from the resulting frontier without manual substitution.
10. If required by the goal, economic/lifecycle continuation and factual runtime projection.

The pure Research Intelligence layer explicitly avoids scheduler mutation; Oracle/refill code exists, but no single real lineage proves the complete join.

## PROMOTION_CRITICAL_PATH

1. Select one exact candidate SHA under explicit authority; branch name is insufficient.
2. SOURCE_SHA/CANDIDATE_SHA relation recorded.
3. Exact-head local qualification on an immutable checkout.
4. Exact-head hosted qualification with TESTED_SHA equality.
5. Remote/current branch equality and clean final identity.
6. Explicit formal promotion decision; no inference from green CI.
7. Deployment/install receipt binding promoted SHA to executable path/config.
8. Independent runtime observation binding installed process to the promoted SHA.

## COMMON_CRITICAL_PREFIX

The only strict prefix common to all three is:

EXACT_IMMUTABLE_IDENTITY -> EXPLICIT_AUTHORITY/CONTRACT -> PROVENANCE_BINDING.

Science then requires real PIT/provenanced observations and scientific controls. Autonomy additionally requires scheduler/task/lease/runtime continuity. Promotion additionally requires exact-head qualification, formal promotion and install/runtime identity. A blocker on one path must not be silently projected onto the other paths.

## DIVERGENT_REQUIREMENTS

- Science does **not** require full autonomous scheduling if experiment identity, data provenance, deterministic execution, adjudication and denominator controls remain valid.
- Autonomy does require the canonical task/lease/runner/evaluator/sink chain and continued operation without manual substitution.
- Promotion can fail even when science is valid, because code-state qualification/authority/install identity are separate claims.
- A hosted qualification failure blocks promotion of that SHA but does not retroactively invalidate scientifically valid historical observations produced by another frozen protocol.
